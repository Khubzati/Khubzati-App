# Khubzati Implementation Matrix

**Methodology:** Every row below is sourced from direct inspection of runtime code — routes, DI registrations, Flutter screens/blocs, API endpoints, controllers, Prisma models/migrations, and tests — across all four repos (`khubzati-app`, `Khubzati-backend-apis`, `admin`, `khubzati-website`). **No root-level `.md` audit/report file was used as evidence for any status below** (see project memory: those files were fabricated in a single commit and contradict each other). Evidence cells cite exact file paths, line numbers, and symbol names so every claim is independently checkable.

Status legend: **Complete** / **Partial** / **UI only** / **Backend only** / **Missing** / **Dead code** / **Broken** (wired end-to-end but factually non-functional, e.g. a value mismatch that always errors).

## Blocker summary (severity = Blocker only, prioritized)

1. Cart is cleared before payment is confirmed for online-card orders (`checkout_screen.dart:867-880`) — real money/inventory risk.
2. Order confirmation screen is fully static and never re-verifies payment server-side; deep-link handler treats any non-cancel redirect as success without calling `GET /orders/:orderId/payment-status` — a tampered or premature redirect could show "Confirmed" for an unpaid order.
3. Restaurant-owner product management (`PUT/DELETE/PATCH /restaurant/products/:id`, `/restaurant/categories`) — routes don't exist; every edit/delete/availability-toggle/category action 404s for restaurant owners.
4. Restaurant order management: Accept has no UI option; "preparing" and "ready for pickup" transitions send status values the backend doesn't recognize and always 400; list/detail responses are parsed with the wrong shape.
5. Driver "available deliveries" happy path is non-functional — app calls an endpoint that can never return data; the correct endpoint is unused.
6. Driver "Report Failed Delivery" discards the driver's input and never calls the API.
7. No vendor-status gate on any write endpoint (`bakery.js`/`restaurants.js`) — a pending/rejected vendor can create products and manage orders; Flutter has no route guard either (direct navigation bypasses UI hiding).
8. Forgot-password screen is unregistered dead code; fully-built backend + bloc plumbing sit unused.
9. Admin banner/content management has no backend at all — fake, non-persistent.
10. Website `/checkout` developer harness (paste-a-JWT) is reachable in production builds.
11. No Privacy Policy / Terms of Service pages exist despite a linked Stripe checkout flow.
12. Product modifiers have no data model at all — if required for launch, this is a schema-level gap, not just UI.

Everything above is addressed, phase-by-phase, starting with Phase 2 (Flutter duplicate/dead-code resolution) next.
